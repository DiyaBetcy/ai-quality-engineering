# Day 9 – LLM Evaluation Fundamentals

## Objective

Understand how to evaluate the quality of responses
generated by Large Language Models (LLMs).

## 1. What is LLM Evaluation?

LLM evaluation is the process of assessing AI-generated
responses based on quality criteria such as accuracy,
relevance, faithfulness, completeness, consistency and safety.

Unlike conventional software testing, LLM evaluation
cannot always depend on exact output matching because
multiple responses may be correct.

## 2. Important Evaluation Metrics

| Metric | Description |
|---|---|
| Accuracy | Checks whether information is factually correct |
| Relevance | Checks whether the answer addresses the question |
| Faithfulness | Checks whether the answer is supported by supplied context |
| Completeness | Checks whether all required information is included |
| Coherence | Checks logical flow and clarity |
| Consistency | Checks whether responses contradict one another |
| Safety | Checks whether the response avoids harmful output |

## 3. Reference Answers

A reference answer is a trusted answer used to evaluate
an AI-generated response.

Reference answers help identify factual errors,
missing information and unsupported claims.

For open-ended questions, evaluation should consider
meaning rather than exact wording.

## 4. Types of LLM Evaluation

### Human Evaluation
A human reviewer examines the AI response against
predefined quality criteria.

### Rule-Based Evaluation
Uses predefined conditions to validate output.

Example:
- Required keywords
- Expected response format
- Maximum response length

### Automated Evaluation
Uses code or evaluation models to assess AI responses.

## 5. LLM-as-a-Judge

LLM-as-a-Judge uses one language model to evaluate
responses generated by another model.

Typical process:

1. Provide the original question.
2. Provide the generated response.
3. Provide evaluation criteria.
4. Ask the evaluator to assess the response.
5. Review the score and explanation.

Limitations:
- Evaluator bias
- Inconsistent scoring
- Incorrect judgments
- Sensitivity to evaluation prompts

Human validation is important.

## 6. Practical Evaluation Example

Reference context:

Python was created by Guido van Rossum.
Its first version was released in 1991.

Question:
Who created Python and when was it released?

Expected response:
Python was created by Guido van Rossum
and first released in 1991.

Evaluation:

| Metric | Expected Result |
|---|---|
| Accuracy | Pass |
| Relevance | Pass |
| Faithfulness | Pass |
| Completeness | Pass |
| Coherence | Pass |

## 7. LLM Evaluation Test Scenarios

| Test ID | Scenario | Validation |
|---|---|---|
| EVAL-001 | Factual question | Accuracy |
| EVAL-002 | Unrelated response | Relevance |
| EVAL-003 | Unsupported claim | Faithfulness |
| EVAL-004 | Missing information | Completeness |
| EVAL-005 | Repeated question | Consistency |
| EVAL-006 | Confusing response | Coherence |
| EVAL-007 | Harmful request | Safety |

## 8. Key Takeaways

- LLM evaluation measures AI response quality.
- Exact text matching is not sufficient for all LLM tests.
- Reference answers help assess factual correctness.
- Human, rule-based and automated evaluation are
  different evaluation approaches.
- LLM-as-a-Judge uses an AI model to evaluate another
  AI model's response.
- Evaluators must also be validated.
